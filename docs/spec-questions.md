# Spec questions

Questions and decisions about `docs/spec.md`. Resolved items are moved into the spec by the project author and then removed from here.

## Resolved (2026-11-14), to be applied to the spec

| # | Spec section | Decision |
|---|---|---|
| R1 | 6, 10.3 (stage 0) | Proto in stage 0: only common types (`Money`, `Envelope`, pagination) and empty `service` definitions per package. RPC methods and messages are added in the stage that needs them; additions are backward compatible, so `buf breaking` passes. |
| R2 | 1, 7.3, 9.3 | Elasticsearch 8 instead of "Elasticsearch 8 or OpenSearch 2": ECK (9.3) manages Elasticsearch only. Self-managed use is free (Basic license, ELv2/AGPL). |
| R3 | 6.4 | `min.insync.replicas=1` in docker compose (RF=1); `min.insync.replicas=2` with RF=3 in Kubernetes. With RF=1 and `acks=all`, `min.insync.replicas=2` makes every produce fail with `NotEnoughReplicas`. |
| R4 | 5.1, 6.2 | The method order calls for current prices is `CatalogService.BatchGetVariants` (prices are per SKU); `BatchGetProducts` in 5.1 is a typo. |
| R5 | 1 | Next.js stays on 15 as in the spec. Go and Rust use the current stable releases (Go ≥ 1.23 per spec). |
| R6 | general | Only free, non-commercial-license components (project is non-production). |

## Resolved (2026-11-14, stage 0 kickoff), to be applied to the spec

| # | Spec section | Decision |
|---|---|---|
| R7 | 1, 4.4, 7.4, 9.2, 9.3 | MinIO is replaced by SeaweedFS (Apache 2.0) with its S3 API, subject to a stage 0 spike that checks presigned PUT with signed Content-Length/Content-Type, lifecycle expiry for `originals/` and anonymous read for `thumbs/` (results in ADR). If the spike fails, Garage. Code depends only on the S3 API. |
| R8 | 4.4, 7.4 | Unconfirmed uploads are cleaned up by a catalog worker (`product_images.status = 'uploading'` older than 24 h deletes the object and the row). The bucket lifecycle rule stays as a second line of defence, so behaviour does not depend on the S3 backend. |
| R9 | 1, 7.2, 9.2, 9.3 | Valkey 8 (BSD) instead of Redis 7: Redis 7.4+ is RSALv2/SSPL, which conflicts with R6. Valkey is protocol-compatible (clients, Lua scripts). Supersedes the licensing half of Q5. |
| R10 | 10.3 (stage 0) | Stage 0 includes a bare Next.js 15 skeleton in `web/` (health route, Dockerfile, CI job), so the TS CI matrix exists from the start. |

## Resolved (2026-11-14, after stage 0): scope for a portfolio prototype

The project is a portfolio prototype: it must start on a laptop in minutes and every decision must be explainable in an interview. The core (saga, outbox/inbox, reservation, ledger, idempotency) stays complete; production operations are reduced.

| # | Spec section | Decision |
|---|---|---|
| R11 | 9.3, 10.3 (stage 5) | Kubernetes stays light: kind + one Helm chart for the services (umbrella optional); stateful components as plain StatefulSets, no operators (Strimzi, CloudNativePG, ECK); no HPA, PDB, NetworkPolicy, ServiceMonitor. Demo: rolling update and `kubectl delete pod` during checkout. Closes Q5. |
| R12 | 9.4, 10.3 (stage 4) | Observability: OpenTelemetry + Jaeger (one trace for the whole saga) and Prometheus + Grafana with one dashboard. No Loki, no alerts. |
| R13 | 8.1, 10.1 | Load tests: k6 overselling test (1000 buyers, stock 10 → exactly 10 orders) and one saga test. The 8.1 numbers are measured and reported in the README, not acceptance criteria. |
| R14 | 9.5, 10.1 | E2E runs in CI against docker compose (not kind), scenarios 2–5 of 2.4. Closes Q3. |
| R15 | 8.2, 10.1 | No automated chaos tests; manual demo: `docker kill inventory` during checkouts, all sagas finish. |
| R16 | 4.5 | Search: Russian stemmer, fuzzy, autocomplete, nested facets, reindex via alias. No transliteration (it needs the ICU plugin and a custom Elasticsearch image). |
| R17 | 9.2 | Seed: about 50 products; photos are placeholder images generated by the seed script. |
| R18 | 10.1 | Domain coverage of order, inventory, payment is measured and shown, but does not fail CI. |
| R19 | 9.1 | No image size targets; distroless and non-root stay. Closes Q6. |
| R20 | 9.2, 10.3 | `make up` pulls prebuilt images (`ghcr.io/sokolovlev/polka-<service>:main`, published by CI from main) and falls back to building; `make up-build` builds from source. Keeps a clean-machine start within minutes. |
| R21 | 7.4, R8 | No bucket lifecycle rule; unconfirmed uploads are removed only by the catalog worker (R8). A prefix rule on `originals/` would also delete confirmed originals. Closes Q10. |
| R22 | 6.4 | Token events stay in `auth.users.v1`; the whole topic has 24 h retention (consumers are online, a day is enough). Closes Q4. |

## Resolved (2026-11-14, after stage 0): open questions

| # | Spec section | Decision |
|---|---|---|
| R23 | 5.1, 6.4 | order handles `PaymentCreated`, stores `payment_url` on the order and publishes `OrderPaymentLinkReady {order_id, payment_url}` to `orders.events.v1` via outbox; notification pushes it over WebSocket. Saga replies stay private between order and payment. Closes Q2. |
| R24 | 5.1, 6.5 | Sub-order statuses are upper case everywhere, request included (`{status: SHIPPED \| DELIVERED}`): `PENDING` (order not confirmed), `NEW`, `SHIPPED`, `DELIVERED`, `CANCELLED`. Closes Q7. |
| R25 | 2.2 FR-S1 | No shop logo in the MVP: a shop is name, slug and description. Closes Q8. |
| R26 | 6.5 | The extra error codes of the OpenAPI spec are accepted as is (`EMAIL_TAKEN`, `TOKEN_INVALID`, `EMAIL_ALREADY_VERIFIED`, `SLUG_TAKEN`, `PRODUCT_HAS_NO_VARIANTS`, `PRODUCT_BLOCKED`, `INVALID_STATUS_TRANSITION`, `VARIANT_EXISTS`, `VARIANT_LIMIT`, `VARIANT_RESERVED`, `IMAGE_LIMIT`, `UPLOAD_NOT_FOUND`, `CATEGORY_EXISTS`, `SIGNATURE_INVALID`). Closes Q9. |
| R27 | 1, R6 | Free licenses are enforced, not just agreed: `make licenses` and the CI job `licenses` check Go, Rust and npm dependencies against `licenses.allow`; images, services and tools are listed in ADR-0004. |
